# pi-oven 사용법

pi(coding agent)를 브라우저에서 쓰는 웹 UI입니다. 서버(Rust)가 세션마다 `pi --mode rpc` 프로세스를 띄우고 WebSocket으로 중계합니다. 세션 기록은 pi가 저장하는 그대로(`~/.pi/agent/sessions`)라서 터미널의 pi와 같은 세션을 공유합니다.

## 1. 실행

```sh
cd web && npm install && npm run build && cd ..   # 프론트를 만들어 서버 바이너리에 포함
cargo build --release
./target/release/pi-oven                          # http://127.0.0.1:4141
```

프론트를 고친 뒤에는 `npm run build` 후 `touch src/web.rs`를 하고 다시 `cargo build --release` 해야 바이너리에 반영됩니다.

개발 중에는 `cargo run`과 `cd web && npm run dev`(5173, `/api` 프록시)를 같이 띄웁니다.

### LAN(다른 기기)에서 쓰기

```sh
pi-oven --lan                         # 토큰을 만들어 출력
pi-oven --lan --password-file ~/pw    # 비밀번호로 접속(파일의 첫 줄)
pi-oven --lan --token-file ~/token    # 토큰을 정해서 접속
```

- 루프백이 아닌 주소(`--lan`, `--host 0.0.0.0` 등)로 열면 토큰이나 비밀번호가 꼭 필요합니다. 둘 다 없으면 토큰을 만들어 출력합니다. 시작 때 접속 주소(LAN IP 포함)를 출력합니다.
- **토큰**: `http://<서버 IP>:4141/#token=<토큰>`으로 접속하면 브라우저에 저장되고 주소창에서 지워집니다. 12자 이상.
- **비밀번호**: 접속 화면에 직접 입력합니다. 8자 이상, 공백 없는 영문·숫자·기호. 토큰과 같이 쓰면 둘 중 아무거나 통합니다.
- 틀리게 8번 입력하면 접속한 주소별로 30초부터(반복하면 두 배씩, 최대 15분) 잠깁니다. 리버스 프록시 뒤에서는 `--trust-proxy`로 접속자별로 셉니다.
- 토큰·비밀번호를 `--token`/`--password`로 주면 `ps`에 보입니다. 환경변수나 `-file` 옵션을 권합니다.
- pi는 셸 명령을 실행하므로, 토큰이 곧 이 PC의 권한입니다. 외부 인터넷에는 직접 열지 말고 VPN이나 HTTPS 리버스 프록시 뒤에 두세요.

### 옵션

| 옵션 | 설명 |
|---|---|
| `--host`, `--port` | 기본 `127.0.0.1:4141` |
| `--lan` | `--host 0.0.0.0`과 같음 |
| `--token`, `--token-file` | 접속 토큰(또는 첫 줄을 읽을 파일) |
| `--password`, `--password-file` | 접속 비밀번호(또는 파일) |
| `--trust-proxy` | 프록시 뒤에서 실패 횟수를 `X-Forwarded-For` 첫 주소별로 셈 |
| `--allow-origin` | 추가로 허용할 브라우저 Origin(반복 가능). 예: `tauri://localhost` |
| `--pi-bin` | 실행할 pi. 기본 `pi`(서버를 띄운 셸의 `PATH`에서 찾음) |
| `--pi-arg=…` | 모든 pi 프로세스에 넘길 인자(반복 가능). 예: `--pi-arg=--approve` |
| `--sessions-dir` | 세션 폴더. 기본 `$PI_CODING_AGENT_SESSION_DIR`, `$PI_CODING_AGENT_DIR/sessions`, `~/.pi/agent/sessions` 순 |
| `--root` | 이 폴더와 그 아래에서만 작업합니다. 폴더 선택은 여기서 시작하고 위로 못 가며, 새 폴더·pi 시작도 이 안에서만 됩니다. 다른 폴더에서 시작한 세션은 목록에 보이지 않고 열거나 지울 수 없습니다. pi 자체(모델이 쓰는 도구)는 바깥을 읽고 쓸 수 있으니 격리가 필요하면 아래 "폴더 밖 접근"을 보세요. |
| `--no-permission-ext` | 내장 권한 확장을 끔(자동/수동 전환이 사라짐) |

환경변수 `PI_OVEN_HOST`, `PI_OVEN_PORT`, `PI_OVEN_TOKEN(_FILE)`, `PI_OVEN_PASSWORD(_FILE)`, `PI_OVEN_PI_BIN`, `PI_OVEN_SESSIONS_DIR`도 같은 역할입니다.

> pi가 여러 개 설치돼 있으면(`which -a pi`) 서버의 `PATH`에서 먼저 나오는 쪽이 쓰입니다. 고정하려면 `--pi-bin /절대/경로/pi`.

## 2. 화면 구성

```
┌ 좌측: 세션 목록 ┬ 가운데: 대화 ─────────────┬ 우측: 패널 ─────────┐
│ 폴더 열기        │ 헤더(제목·폴더····)       │ 정보 │ 파일 │ Diff │ Git │ Pin │
│ 검색             │ 대화                       │                     │
│ 폴더별 세션      │ 입력창(권한·모델·추론)     │                     │
│ 설정             │                            │                     │
└──────────────────┴────────────────────────────┴─────────────────────┘
```

- **폰/좁은 화면**: 목록과 우측 패널이 전체 화면 서랍으로 열립니다. 헤더 왼쪽 버튼이 세션 목록, 오른쪽이 패널입니다.
- **좌측 접기**: 목록 위쪽의 사이드바 아이콘으로 56px 아이콘 띠로 접힙니다. 띠에는 폴더 열기, 검색, 열린 세션(폴더 첫 글자 칩), 설정이 남고, 검색 아이콘을 누르면 펼쳐지며 검색창에 포커스가 갑니다. 접힘 상태는 기억됩니다(폰에서는 적용 안 함).
- **우측 패널**: 왼쪽 가장자리를 드래그해 너비를 조절합니다(더블클릭하면 초기화, 방향키로도 조절). 선택한 탭과 너비는 기억됩니다.

## 3. 세션

- **다른 폴더로 옮기기**: 세션 우클릭 메뉴에서 고릅니다. 폴더를 고르면 그 폴더를 작업 폴더로 하는 새 세션에 대화가 모든 분기째 복사되어 열리고, 원래 세션을 지울지 묻습니다(지우지 않으면 그대로 남음). 입력창에는 "작업 폴더를 옮겼다"는 안내 문장이 채워집니다. 이전 기록 속 경로는 예전 폴더 기준이라 보내 두는 편이 안전합니다. 작업이 진행 중인 세션은 끝난 뒤에 옮길 수 있습니다.
- **폴더 접기**: 폴더 이름을 누르면 접히고 펼쳐집니다. 기본은 접힘이라 열려 있는 세션만 보이고, 닫힌 세션 수는 이름 옆 숫자로 나옵니다. 펼친 폴더는 이 브라우저에 기억됩니다. 검색 중이거나 삭제할 세션을 고르는 동안에는 모두 보입니다.
- **폴더 열기**: 작업할 폴더를 고르면 그 폴더에서 새 pi 세션이 시작됩니다. 경로 칸 오른쪽의 폴더+ 버튼으로 지금 보는 폴더 안에 새 폴더를 만들고 바로 들어갈 수 있습니다.
- **이전 세션 이어가기**: 좌측 목록에서 세션을 누릅니다. 열린 세션은 점으로 표시되고, 작업 중이면 깜빡입니다.
- **우클릭(길게 누르기) 메뉴**: 열기, 이름 바꾸기(그 자리에서 입력, 비우면 이름이 지워짐), 그 폴더에서 새 세션, 경로 복사, 세션 트리 보기, 삭제, 여러 개 선택해서 삭제. 모든 메뉴 항목에는 테마 색을 따르는 아이콘이 붙습니다.
- **여러 개 삭제**: 메뉴에서 선택 모드로 들어가 체크박스로 고른 뒤 한 번에 삭제합니다(열려 있는 세션도 고를 수 있고, 닫은 뒤 지웁니다. 다른 기기에서 열려 있어도 닫힙니다). 삭제는 되돌릴 수 없습니다.
- **헤더의 "···"**: 이름 바꾸기, 컨텍스트 압축, 새 세션, 세션 트리, 변경 파일(Diff 탭 열기), 세션 닫기.
- 제목을 누르면 이름을 바꿀 수 있습니다.

### 할 일 (`@juicesharp/rpiv-todo`가 설치된 경우)
모델이 `todo` 도구로 관리하는 작업 목록이 입력창 바로 위에 한 줄로 나옵니다. 작업마다 칸 하나(초록=완료, 앰버=진행 중, 빈 칸=대기, 점선=다른 작업이 끝나야 시작 가능), 지금 하는 일, `2 / 7` 순입니다. 누르면 전체 목록이 위로 열리고(완료는 취소선, "#3 끝나면" 같은 대기 이유 표시) 열림/접힘은 기억됩니다. 작업이 끝나면 그 칸이 한 번 튀어 오릅니다. 오른쪽 ×로 숨기면 목록이 바뀔 때까지 숨습니다. 배경 작업 칩이 맨 위, 그 아래 대기 중인 메시지 카드, 할 일 줄, 맨 아래 입력창 순서입니다(할 일 줄은 항상 입력창에 붙어 있어 대기열이 생겨도 움직이지 않습니다). 목록의 마지막 작업이 끝나면 할 일 줄 전체가 한 번 튀어 오릅니다. 목록은 대화에 남은 `todo` 호출에서 읽고, 압축되었거나 다른 도구(`codemode`)로 부른 호출은 패키지가 세션 파일에 저장해 둔 상태(`rpiv-todo-state`)에서 읽습니다. 패키지가 없으면 아무것도 나오지 않습니다. 이 기능은 애드온(`web/src/addons/todo.ts`)이라 다른 패키지의 UI와 섞이지 않습니다.

### 업데이트 (`pi-updater`가 설치된 경우)
`pi-updater`는 세션이 시작될 때마다 새 버전을 확인하고 선택 창으로 묻는데, 설치 진행은 터미널 전용 화면이라 RPC에서는 눌러도 아무 일이 없습니다. 그래서 서버가 이 질문에는 대신 "건너뛰기"로 답하고(창이 뜨지 않음), 알려 준 내용을 세션 목록 아래에 **업데이트 가능** 카드로 보여 줍니다. 카드의 **업데이트**를 누르고 확인하면 서버 PC에서 `pi update --self`/`--extensions`를 홈 폴더에서 실행합니다(최대 5분). 실패하면 출력을 펼쳐 볼 수 있고, 성공하면 **세션 다시 시작**으로 작업 중이 아닌 열린 세션을 새 pi로 다시 띄웁니다(작업 중인 세션은 끝난 뒤 다시 시작). 제목과 선택지가 `pi-updater`의 것과 정확히 같은 질문만 가로채고, 다른 선택 창은 그대로 뜹니다. 패키지가 없으면 카드도 없습니다.

### 대화 블록의 동작
메시지·답변 블록 바로 아래에 아이콘 버튼이 있습니다(마우스를 올리면 나타나고, 터치 화면에서는 항상 옅게 보임). 사용자 메시지: 복사, 입력창에 넣기, 분기, 다시 생성, 여기부터 지우기. 답변(한 턴의 마지막): 복사, 다시 생성. 분기·다시 생성·지우기는 모두 **새 세션**에서 이어지며 원래 세션은 그대로 남습니다(pi에는 기록 중간을 지우는 기능이 없기 때문). 이미지가 붙은 메시지는 다시 생성할 수 없습니다. 답변 아래에는 **tok/s와 첫 글자까지 걸린 시간(TTFT)**이 나옵니다. 둘 다 브라우저가 이벤트를 받는 시각으로 잽니다. tok/s는 제공자가 출력 토큰 수를 알려 주면 그 값으로, 아니면 글자 수로 추정하고 앞에 `~`를 붙입니다. TTFT는 메시지를 보낸 뒤 첫 글자를 받기까지라 네트워크 지연이 포함됩니다. 사용자 메시지·답변의 **핀 아이콘**은 그 대화를 Pin 탭에 고정합니다(누르면 그 위치로 이동). 시간과 토큰 수는 창이 넓으면 본문 왼쪽 여백에, 좁으면 이 줄 끝에 나옵니다. 대화 본문은 입력창과 같은 너비이고, 대화 스크롤바는 숨겨져 있습니다(휠·터치·키로는 그대로 스크롤).

### 응답 대기 표시
메시지를 보낸 직후부터 모델의 첫 글자가 올 때까지(그리고 도구가 끝나고 다음 답을 기다리는 동안) 답변 자리에 스피너와 상태 글자가 나옵니다. 기본은 "대기 중"이고, 2초가 넘으면 경과 시간이 붙습니다. 컨텍스트 압축 중이면 "컨텍스트 압축 중", 자동 재시도 중이면 "다시 시도하는 중 (1/3)"으로 나옵니다. pi는 네트워크 지연과 프롬프트 처리 시간을 따로 알려주지 않아서 그 둘은 구분하지 못합니다.

### 100h 모드
pi는 일시적인 API 오류(과부하, 5xx 등)를 2·4·8초 간격으로 3번 다시 시도합니다. 그래도 실패하면 대화 위 띠가 주황색으로 바뀌고, 60분마다 최대 100번 다시 시도합니다(한 번의 시도 안에서도 pi의 3번 재시도가 그대로 돕니다). 띠에는 남은 시간과 횟수가 나오고, "지금 시도"와 "그만두기"를 누를 수 있습니다.

- 일정은 서버에 있어서 브라우저를 모두 닫아도 계속되고, 어느 기기에서 열어도 같은 띠가 보입니다.
- 기다리는 동안 새 메시지를 보내면 실패한 요청 대신 그 메시지로 이어지고 대기는 끝납니다.
- 다시 시도는 대화에 보이지 않는 짧은 메시지로 턴을 다시 시작하는 방식입니다. 같은 실패 줄은 하나로 합쳐 보입니다.
- pi가 재시도하지 않는 오류(잘못된 키, 요금제 한도 등)는 대상이 아닙니다.
- pi 프로세스나 서버가 다시 시작되면 대기는 사라집니다.
- 설정 → 대화 → API 재시도에서 끄고 켭니다(기본 켜짐). 서버에 저장되어 모든 기기에 적용됩니다.

### pi-oven 업데이트
설정 → 정보에서 "업데이트 확인"을 누르면 GitHub 최신 릴리즈의 서버 파일을 내려받아 SHA256SUMS와 맞는지 확인하고, 지금 실행 중인 바이너리와 해시로 비교합니다(같은 버전 번호로 파일만 바뀌는 릴리즈도 알아봅니다). 결과 아래에는 그 릴리즈의 노트와 빌드 시각이 펼쳐집니다(최신이면 접혀 있음). 새 빌드가 있으면 "업데이트 후 재시작"으로 바이너리를 바꾸고, 열린 pi를 모두 닫은 뒤 처음 실행할 때와 같은 인자·환경변수로 다시 시작합니다(같은 프로세스). 서버가 새 빌드로 돌아오면 페이지가 새로 열립니다.

- 서버가 켜진 지 30초 뒤와 그 뒤 6시간마다 스스로 확인합니다. 평소엔 `SHA256SUMS`만 받아 서버 파일 해시가 지난번과 같은지 보고, 바뀌었을 때만 파일을 받아 비교합니다(결과는 `~/.cache/pi-oven/update-known.json`). 새 빌드가 있으면 목록 아래에 "pi-oven 새 빌드" 카드가 뜹니다. pi 업데이트 카드와 같은 모양이고, 둘 다 있으면 pi-oven 카드가 위에 쌓입니다. 카드의 글자를 누르면 설정 → 정보로 가고, "업데이트"는 한 번 물은 뒤 바로 바꾸고 다시 시작하며, ×는 그 빌드에 대해서만 숨깁니다. 설정 → 정보의 "업데이트 자동 확인"으로 끕니다.
- 터미널에서는 `pi-oven update`(바꾸기만, 실행 중인 서버는 직접 다시 시작) 또는 `pi-oven update --check`(확인만).
- 서버 PC에 `curl`과 `tar`가 있어야 하고, 바이너리가 있는 폴더에 쓸 권한이 필요합니다(`/usr/local/bin` 등은 권한 오류로 알려 줌).
- 지금은 Linux x86_64(과 aarch64 파일이 있으면 그것)만 됩니다. 직접 빌드한 바이너리는 해시가 달라 늘 "새 빌드가 있습니다"로 나옵니다.

### 폴더 밖 접근
`--root`는 pi-oven이 하는 일(폴더 탐색, 새 폴더, pi를 어디서 시작할지, 어떤 세션을 보여 줄지)만 묶습니다. 모델이 쓰는 도구(bash, read, edit 등)는 pi가 서버와 같은 사용자 권한으로 실행하므로, 시작 폴더 밖의 파일도 읽고 쓸 수 있습니다. 권한 모드를 "수동"으로 두면 명령 실행과 파일 수정 전에 묻지만, 파일 읽기는 막지 않습니다. 정말 막으려면 운영체제 수준의 격리(컨테이너, 전용 사용자, bubblewrap 등)가 필요합니다.

### 구독 한도
ChatGPT(Codex) 구독으로 쓰는 동안 입력창 아래 줄, 컨텍스트 링 왼쪽에 한도 칩이 나옵니다. 원을 세로 홈으로 가른 모양으로, 왼쪽 반은 주간, 오른쪽 반은 5시간의 남은 양이며 쓸수록 위에서부터 줄어듭니다. 숫자는 5시간 창의 남은 %입니다. 25% 아래로 내려가면 앰버, 한도에 닿으면 빨간 반쪽과 가운데 `!`가 나오고 숫자 대신 초기화까지 남은 시간이 나옵니다. 누르면 두 창의 남은 양과 초기화 시각이 나오고, "정보 탭에서 보기"로 우측 정보 탭의 구독 한도 카드(받아 둔 구독 전부)로 갑니다.

- 값은 응답이 올 때 같이 오는 숫자입니다. 따로 묻지 않으므로 마지막 응답 시점의 값이고, 카드에 "몇 분 전 응답 기준"으로 나옵니다. 초기화 시각이 지나면 0%로 돌아갑니다.
- 서버가 구독마다 마지막 값을 저장해 두어서 다른 세션·기기에서도, 서버를 다시 켜도 보입니다.
- 로컬 모델이나 API 키 모델에는 칩이 나오지 않습니다.
- 설정 → 대화 → 입력창 아래 표시에서 컨텍스트 링, 구독 한도 칩, 칩 옆 숫자를 각각 끄고 켭니다(이 브라우저에 저장).
- Claude 구독은 응답 헤더(`anthropic-ratelimit-unified-*`)를 읽도록 만들어 두었지만 실제 계정으로는 확인하지 못했습니다.

### Zero-Waste
ChatGPT 구독의 사용량 한도(5시간 등)에 걸려 응답이 멈추면, 한도가 초기화된 뒤 정해 둔 문구(기본 "계속해")를 보내 이어서 진행합니다. 대화 위 주황 띠에 남은 시간과 보낼 문구가 나오고 "지금 보내기", "그만두기"를 누를 수 있습니다.

- 띠에는 `한도 도달 · 2:00:51 뒤 "계속해"`처럼 남은 시간과 문구만 나오고, 어느 한도(5시간·주간)가 몇 시에 풀리는지는 띠의 툴팁에 있습니다.
- 언제 보낼지는 오류에 적힌 시간("Try again in ~42 min")이 있으면 그것, 없으면(ChatGPT는 "The usage limit has been reached"만 옴) 마지막 응답 때 받은 한도 값에서 가장 많이 쓴 창의 초기화 시각, 그것도 없으면 1시간 뒤입니다. 1분도 버리지 않도록 초기화 10초 뒤에 보내고, 그때 아직 막혀 있으면(초기화 직후 10분 안에 다시 한도) 1분 뒤 다시 보냅니다. 그 창은 소진(남은 양 0%)으로 표시됩니다.
- 일정은 서버에 있어 창을 닫아도 계속되고 다른 기기에서도 같은 띠가 보입니다. 그 전에 직접 메시지를 보내면 대기는 끝납니다.
- 걸린 한도가 주간(하루보다 긴 창)이면 기다리지 않고, 언제 풀리는지만 알립니다. 어느 창인지는 마지막 응답 때 받은 한도 값에서 가장 많이 쓴 창으로 정합니다.
- 보낸 문구가 다시 한도에 걸리면 또 기다리고, 10번 연속이면 멈춥니다.
- 설정 → 대화 → 구독 한도에서 끄고 켜고 문구를 바꿉니다(서버에 저장, 모든 기기 공통).
- 한도 오류에는 100h 모드가 붙지 않습니다(몇 시간 뒤에야 풀리므로 이쪽이 맡음). Claude 구독의 한도 오류 문구는 실제로 확인하지 못했습니다.

### 도구 호출의 경과 시간
도구 호출(bash 등)이 3초를 넘기면 그 줄 오른쪽에 경과 시간이 앰버색으로 올라갑니다. 끝나면 pi가 잰 시간으로 바뀝니다. 이 페이지가 시작을 직접 본 호출만 세고, 기록을 다시 불러온 것은 세지 않습니다.

### 입력창

- `Enter` 전송, `Shift+Enter` 줄바꿈, `Tab`/`Shift+Tab` 들여쓰기·내어쓰기(공백 2칸, 여러 줄을 선택하면 그 줄 모두). 작업 중에 `Enter`는 방향 전환(steer), `Alt+Enter`는 이어서 보내기(follow-up), `Ctrl+Enter`는 즉시 보내기입니다. 터치 화면에서는 `Enter`가 줄바꿈이고 전송은 버튼으로 합니다.
- **즉시 보내기**: 작업 중 입력창의 번개 버튼(또는 `Ctrl+Enter`)은 지금 작업을 멈추고, 대기 중이던 메시지와 새로 쓴 내용을 한 메시지로 묶어 바로 보냅니다. 대기 중인 메시지는 할 일 줄 위에 카드로 모여 보이고, 카드의 "즉시 보내기"는 입력 없이 대기열만 바로 보냅니다. 대기열에 있던 메시지의 이미지는 함께 가지 않습니다(pi가 글자만 돌려줌).
- `/`로 시작하면 pi의 명령(스킬·프롬프트·확장)이 목록으로 나옵니다.
- 아래쪽 선택기: **권한(자동/수동)**, **모델**, **추론 강도**, 컨텍스트 사용량 링.
- 수동 권한이면 읽기 전용이 아닌 도구 호출 전에 웹에서 허락을 묻습니다. 고른 모드는 서버(`~/.cache/pi-oven/permission`)에 저장되어 모든 기기와 새로 여는 세션에 같이 적용되고, 이미 열린 다른 세션은 다음 도구 호출 때 따라갑니다.
- 백그라운드 작업(`bg_run`)은 작업마다 입력창 위에 칩이 하나씩 생깁니다. 시작할 때 도구 줄에서 튀어나와 자기 칩에 안착하고(여러 개면 잠시 모아서 이름순(숫자는 숫자로 읽음, 시작 시각이 1초 넘게 다르면 시간순)으로 자리를 정한 뒤 한 개씩 차례로 왼쪽부터), 끝나면 그 칩이 한 번 튀어 오르며 결과 색의 링이 퍼집니다. 끝난 작업을 pi가 대화에 알리면(알림 말풍선) 칩이 자기 점으로 오그라들어 그 말풍선으로 날아가 들어가고, 말풍선은 불씨가 도착한 뒤에 나타납니다. 알림이 오지 않으면 성공한 칩은 10초 뒤 사라지고, 실패·중단은 × 로 닫을 때까지 남습니다. 폭에 들어가지 않는 실행 중 작업은 줄 끝의 작은 원에 `+N`으로 쌓입니다. 실행 중인 칩에는 "실행 중" 대신 경과 시간(`2:07`, 고정폭 숫자, 앰버색)이 나옵니다. 서버가 알려 준 시작 시각을 기준으로 해서 새로고침하거나 다른 기기에서 열어도 이어서 세지만, 서버와 이 기기의 시계가 많이 다르면 어긋납니다. 칩을 누르면 목록이 그 작업을 펼친 채 열리고, 말풍선의 "출력 보기"도 같습니다.

## 4. 세션 트리 (분기)

세션 기록은 가지를 칠 수 있는 트리입니다. 목록 우클릭 → "세션 트리 보기", 또는 열린 세션의 "···" → "세션 트리".

- 사용자 메시지 하나와 그 뒤 응답을 한 줄로 묶어 보여줍니다. 진한 점이 지금 이어지는 흐름이고, 다른 갈래는 들여쓰기로 나옵니다.
- 줄을 펼치면:
  - **이 메시지부터 다시 쓰기**: 그 메시지 직전까지의 대화로 새 세션을 열고, 입력창에 그 메시지를 채워 줍니다.
  - **여기까지로 새 세션 열기**: 그 턴이 끝난 시점까지의 대화로 새 세션을 엽니다.
- **원본 세션은 바뀌지 않습니다.** 고른 지점까지의 기록을 새 세션 파일로 복사해서 엽니다. 닫힌 세션에도 쓸 수 있습니다.

## 5. 우측 패널

### 정보
컨텍스트 사용률, 토큰·비용, 확장 상태, 세션 파일 경로.

### 파일 (탐색기)와 편집기
세션 폴더의 파일 트리입니다. 폴더 안으로만 보이며(`.git`은 숨김, 폴더 밖을 가리키는 링크는 흐리게 표시되고 열리지 않음) pi가 파일을 쓰면 자동으로 다시 읽습니다.

- **열기**: 파일을 누르거나, 가운데(대화 영역)로 끌어다 놓으면 편집기 탭으로 열립니다. 탭은 맨 앞 "대화" 옆에 쌓이고, 새로 고침해도 열려 있던 탭이 복원됩니다(저장하지 않은 내용은 복원되지 않음). 파일을 입력창으로 끌면 경로가 메시지에 들어갑니다.
- **편집**: 줄 번호, 구문 색상(js/ts/json/html/css/md/py/rs/yaml/sh/toml 외), 되돌리기(`Ctrl+Z`), 찾기(`Ctrl+F`), 들여쓰기(`Tab`), 긴 줄 바꿈 토글. `Ctrl+S`로 저장하고, 저장하지 않은 탭에는 주황 점이 붙습니다. UTF-8 텍스트만 열립니다(2MB까지). CRLF 줄바꿈과 BOM은 저장할 때 원래대로 돌려 놓습니다.
- **pi와 같이 쓰기**: 열어 둔 파일은 2.5초마다 디스크와 비교합니다. 건드리지 않은 탭은 pi가 고친 내용을 자동으로 불러오고, 내가 고치던 탭은 "디스크의 파일이 바뀌었습니다" 배너가 떠서 디스크 내용을 불러올지, 내 내용으로 덮어쓸지 고릅니다. 디스크가 더 새로운 상태로 저장하려 하면 서버가 거절합니다(아무것도 덮어쓰지 않음).
- **트리 조작**: 우클릭(길게 누르기)으로 새 파일·새 폴더·이름 바꾸기·삭제·경로 복사. 키보드는 방향키, `Enter`, `F2`(이름 바꾸기), `Delete`. 삭제는 휴지통 없이 영구 삭제이며 확인창이 먼저 뜹니다.
- **이미지**: PNG·JPG·GIF·WebP·AVIF·BMP·ICO·SVG는 그림으로 열립니다(투명한 부분은 바둑판 무늬, 아래에 크기와 용량, 30MB까지). 편집은 안 되고, 파일이 바뀌면 다시 불러옵니다. SVG는 그림으로만 보여 주고 안의 스크립트는 실행하지 않습니다.
- **실시간 반영**: pi가 열어 둔 파일을 고치면 바뀐 줄만 편집기에 반영되고(커서·스크롤·되돌리기 기록 유지, 바뀐 줄이 잠깐 빛남) 내가 고치던 탭도 서로 다른 줄이면 자동으로 합칩니다. 같은 줄이거나 맞닿은 줄, 파일 전체가 바뀐 경우, 500KB가 넘는 파일은 합치지 않고 배너로 묻습니다. 같은 변경이 두 번 연속 확인될 때만 받아들이므로 쓰는 도중의 파일은 반영하지 않습니다. 합쳐진 내용도 내가 저장하기 전에는 디스크에 쓰지 않습니다.
- **대화와 나란히**: 가운데 영역이 충분히 넓으면(약 860px 이상) 편집기 탭 오른쪽 끝의 버튼으로 대화와 편집기를 나란히 둘 수 있습니다(가운데 선을 끌어 폭 조절, 기억됨). 좁으면 탭으로 보이고, 파일이 열려 있는 동안 pi의 작업 상태와 마지막 답이 입력창 위에 한 줄로 나옵니다(누르면 대화로 이동, 새 답이 오면 "대화" 탭에 점).
- **선택한 코드 보내기**: 편집기에서 줄을 선택하면 입력창 위에 `src/main.rs:12-18` 칩이 생기고, 메시지를 보낼 때 그 범위와 코드가 함께 갑니다(× 로 빼기). 선택이 없으면 흐린 칩의 "첨부"를 눌러 파일 이름만 알릴 수 있습니다. 폰에서는 파일이 열려 있는 동안 모델·권한 줄이 접히고, 입력창을 누르면 펼쳐집니다.
- 탭을 닫거나 세션을 닫을 때 저장하지 않은 내용이 있으면 확인합니다.

### Diff
pi가 `edit`·`write`로 **성공시킨** 변경을 실시간으로 보여줍니다. 디스크의 파일은 읽지 않고, pi가 돌려준 diff를 보여줍니다.

- 수정 중인 파일은 "수정 중…"으로 표시됩니다.
- 같은 파일을 여러 번 고치면 수정이 번호순으로 나열됩니다.
- "따라가기"를 켜면 새 수정이 생길 때 그 파일을 자동으로 펼칩니다.
- `bash`로 바뀐 파일은 여기 나오지 않습니다. Git 탭을 보세요.

### Git
세션 폴더가 속한 저장소의 상태입니다(저장소가 아니면 안내만 나옵니다).

- 마지막 커밋 이후 바뀐 파일과 `+/-` 줄 수. 파일을 누르면 diff가 펼쳐집니다.
- 체크박스 = 스테이지. 일부만 스테이지된 파일은 중간 상태로 보입니다. "전체 선택"도 있습니다.
- 커밋 메시지를 쓰고 **N개 파일 커밋**(또는 `Ctrl+Enter`). 저장소의 훅(pre-commit 등)은 일반 `git commit`처럼 실행되고, 실패하면 출력이 패널에 나옵니다. git의 사용자 이름/이메일이 설정돼 있어야 합니다.
- `.gitignore`에 걸린 파일은 "무시됨" 접이식 안에 흐린 글씨로 나옵니다.
- 최근 커밋 8개.
- pi가 작업하는 동안 4초마다, 작업이 끝나면 한 번 갱신됩니다. 새로 고침 버튼도 있습니다.

### Pin
개발 중 계속 봐야 하는 값과 대화를 모아 둡니다.
- **대화 고정**: 대화 블록 아래 핀 아이콘으로 고정한 메시지. 눌러서 원래 위치로 이동합니다.

- **대화에서 찾은 주소**: 서버가 출력한 `http(s)://…`와 `localhost:3000`, `127.0.0.1:8080` 같은 주소. 클릭하면 새 탭에서 열립니다. `0.0.0.0`/`localhost` 주소는 다른 기기에서 접속 중이면 접속한 호스트로 바꿔서 엽니다. 주소 안의 `token=` 값은 가려서 보여주고 복사하면 전체가 복사됩니다.
- **토큰으로 보이는 값**: `token`/`secret`/`api_key`/`password` 이름 뒤의 값, `--token 값`, `Bearer 값`, GitHub·`sk-`·AWS·Slack·JWT·UUID 형식. 한글 이름(`토큰:`, `비밀번호는 …`)과 전각 콜론(`token：`)도 봅니다. 파일 이름·경로 속 UUID는 제외. 가려져 있고 눈 아이콘으로 펼칩니다. 휴리스틱이라 놓치거나 잘못 잡을 수 있습니다.
- **Pin 감지 규칙(regex)**: 설정 → "Pin 감지 규칙"에서 이름과 정규식을 추가하면 그 값도 이 목록에 올라옵니다(괄호가 있으면 첫 괄호 안쪽, 없으면 맞은 부분 전체). 켜고 끄기·지우기 가능, 20개까지, 이 브라우저에만 저장됩니다. 쇼케이스의 "토큰·비밀번호·API 키"를 켜면 대화 속에서도 가려집니다. 되돌림(backtracking)을 멈출 수 없어서 `(a+)+`처럼 반복 안에 반복이 있는 패턴, 200자 넘는 패턴, 빈 글자에 맞는 패턴은 거부합니다.
- **고정**: 핀 아이콘으로 고정하거나 직접 입력해서 고정합니다. 폴더 단위로 저장되며 **이 브라우저의 `localStorage`에 평문으로** 저장됩니다(다른 기기와 공유되지 않음).
- 읽는 범위는 사용자 메시지, 답변, 도구 호출 인자·출력, bash 결과입니다(생각 블록은 제외). 서버로 보내지 않고 브라우저에서만 처리합니다.

## 6. 설정

좌측 아래 설정 아이콘. 탭으로 나뉘어 있습니다(데스크톱은 왼쪽 세로 탭, 폰은 위쪽 칸, 방향키로 이동, 마지막 탭을 기억).

- **화면**: 언어, 테마(시스템/라이트/다크), 글꼴(메이플스토리 또는 시스템), 글자 크기, 답변이 나타나는 효과
- **대화**: 도구 결과 이미지(항상 보기 / 펼쳐서 보기), 생각 블록을 작성 중에 펼치기, 알림(탭이 백그라운드일 때 작업이 끝나거나 질문이 생기면 알림, 브라우저 권한 필요)
- **Pin 규칙**, **모델**, **쇼케이스**, **연결**(서버 주소): 아래 설명
- **정보**: 맨 위에 pi 버전(새 버전이 있으면 표시), 그 아래 pi-oven 버전, 설치된 pi 패키지(`settings.json`의 `packages`, npm 패키지는 버전과 설명, 업데이트가 있으면 표시), MCP 서버(`mcp.json`의 서버 이름·연결 방식, `pi-mcp-adapter` 캐시의 도구·프롬프트 수). MCP의 명령·주소·환경 변수·헤더는 서버가 보내지 않습니다.

- **언어**: 한국어와 English. 처음에는 브라우저 언어를 따르고(파일이 없으면 English), 설정의 언어나 세션 목록 아래 지구 버튼(현재 언어 코드 표시)으로 바꿉니다. 바로 바뀌고 이 브라우저에 기억합니다. 문구는 `web/src/locales/<코드>.json`에 있고, 파일 하나를 추가해 빌드하면 새 언어가 목록에 나옵니다(`web/src/locales/README.md`, 검사는 `cd web && npm run i18n`).

- **모델 추가·관리**: 설정 → 모델 탭에 추가해 둔 제공자(주소, 키 힌트, 모델)가 보이고, 같은 자리에서 추가·수정·삭제합니다. 입력창의 모델 메뉴 맨 아래 "모델 추가…"를 누르면 이 탭이 열립니다. 제공자 이름, API 방식(OpenAI 호환 / OpenAI Responses / Anthropic / Google), 엔드포인트 주소(`http://localhost:8000/v1`), API 키, 모델 ID를 적으면 pi의 `models.json`(`PI_CODING_AGENT_DIR` 또는 `~/.pi/agent/`)에 저장합니다. "서버에서 모델 불러오기"는 `GET {주소}/models`로 모델 ID 목록을 받아 고르게 해 줍니다. 키는 파일에만 저장되고 화면에는 앞뒤 몇 글자 힌트만 나옵니다(비워 두면 저장된 키를 그대로 둠, `$환경변수`·`!명령` 형식도 가능). 저장 전에 `models.json.bak`으로 백업합니다. 지금 열린 세션에 안 보이면 "세션 다시 열기"를 누르세요.
- **쇼케이스 모드**: 화면 공유·스크린샷용. 켜면 항목별 스위치(프로젝트 폴더 경로, 사용자 이름·홈 폴더, 세션 제목, 토큰·키, 서버 주소·IP, 파일 이름, 대화 본문)로 가릴 것을 고릅니다. 가리는 방식은 **예시 글자로 바꾸기**(기본) 또는 **흐리게**. 예시 글자는 (폴더는 `example-project`, 세션은 `예시 세션`, 대화 속 경로는 `<프로젝트>`(영어에서는 `Example session`, `<project>`), 주소는 `server` 등). 보이는 모습만 바뀌고 저장·복사되는 내용은 그대로입니다. 입력 칸과 코드 편집기는 글자를 바꿀 수 없어 항상 흐리게 처리합니다. 사이드바 아래에 켜져 있다는 표시가 나옵니다.
- **모달**: 열린 창의 바깥 빈 곳을 누르면 닫힙니다.
- **파일 아이콘**: 확장자·파일 종류별로 모양과 색이 다른 아이콘(탐색기, 편집기 탭, Git, Diff).

## 7. 데스크톱 앱 (Tauri)

`desktop/`는 pi-oven 서버에 연결하는 얇은 창입니다. 화면은 서버가 내려주는 웹 UI 그대로라 앱을 다시 설치할 일이 없습니다. 서버는 따로 띄워야 합니다.

- 처음 실행하면 서버 주소(예: `localhost:4141`)와 토큰(선택)을 입력합니다. 주소는 이 PC에 저장되고(`~/.config/dev.code4hub.pioven/server.txt`, 본인만 읽기), 다음부터는 바로 서버 화면이 열립니다.
- **폰(안드로이드)**: 저장된 서버가 있으면 앱을 열 때 스스로 연결합니다(토큰도 함께 저장되어 다시 입력하지 않습니다). 서버를 바꾸려면 연결 중 화면의 "취소하고 서버 바꾸기"를 누르거나, 연결된 뒤 뒤로 가기를 누르세요.
- 창에 메뉴 줄은 없습니다(일부 리눅스 데스크톱에서 화면 크기 계산을 틀어지게 해서 뺐습니다). 다른 서버로 바꾸려면 앱을 `--server 주소`(또는 환경변수 `PI_OVEN_SERVER`)로 실행하거나, 저장된 `server.txt`(리눅스 `~/.config/dev.code4hub.pioven/`, 윈도우 `%APPDATA%\dev.code4hub.pioven\`)를 지우면 처음 화면이 나옵니다. 서버 화면의 외부 링크는 시스템 브라우저로 열립니다.
- `--server <주소>`나 `PI_OVEN_SERVER`로 저장된 주소 대신 쓸 서버를 줄 수 있습니다.
- 빌드: `cd desktop && cargo tauri build`(deb, AppImage) 뒤에 **`desktop/scripts/fix-appimage.sh`** 로 AppImage를 다시 묶습니다. 빌드 PC의 libwayland를 빼고(다른 배포판의 Mesa와 섞이면 죽어서 linuxdeploy가 X11을 강제하던 원인), 그 강제를 지웁니다. 서버 화면에는 앱의 기능(IPC) 권한이 없습니다. Linux만 빌드해 확인했고 Windows·macOS는 빌드하지 않았습니다.
- **리눅스 AppImage의 실행 환경**: 앱이 시작할 때 정합니다(사용자가 직접 준 값이 항상 우선).
  - Wayland 세션이면 네이티브 Wayland로(`GDK_BACKEND=wayland,x11`), 아니면 X11.
  - fcitx/fcitx5: AppImage 안에는 fcitx 입력 모듈이 없어서, Wayland에서는 컴포지터의 입력기(text-input, `GTK_IM_MODULE=wayland`)를, X11에서는 XIM(`XMODIFIERS=@im=fcitx`)을 씁니다. 그 밖에 AppImage에 없는 모듈을 요청하면 GTK가 고르게 둡니다.
  - NVIDIA 독점 드라이버에서만 WebKit의 DMA-BUF 렌더러를 끕니다(검은 창 방지). 다른 GPU에서는 켜 둡니다.
  - 무엇이 정해졌는지 보려면 `PI_OVEN_DEBUG_ENV=1`로 실행하세요. 문제가 있으면 `GDK_BACKEND=x11`이나 `WEBKIT_DISABLE_DMABUF_RENDERER=1`을 직접 주어 바꿀 수 있습니다.
  - 네이티브 tar.gz는 시스템의 GTK·입력기 모듈·드라이버를 그대로 써서 이 조정이 필요 없습니다. AppImage에서 계속 문제가 있으면 이쪽을 쓰세요.

## 8. 데스크톱 펫 연동 (선택)

서버는 `/api/pet/stream`으로 작업 상태를 내보내고, 별도 프로그램 `oven-pet`이 이를 받아 데스크톱 캐릭터로 반응합니다. 펫을 우클릭하면 연결(주소, 토큰), 동작 재생, 캐릭터 변경 메뉴가 나옵니다. 자세한 내용은 `oven-pet/README.md`를 보세요.

## 9. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| "서버에 연결할 수 없습니다" | 서버가 떠 있는지, 포트가 맞는지, 방화벽 |
| 토큰 입력 화면이 계속 나옴 | 서버를 다시 띄우며 `--token`이 바뀌지 않았는지 |
| 폰에서 앱을 백그라운드로 보냈다 오면 "연결 중" | 폰이 잠든 연결은 끊깁니다. 앞으로 돌아오면 바로 다시 연결하는데(안 되면 4초 안에 감지), 서버의 pi 세션은 그대로 살아 있습니다. 연결이 시도마다 실패하면 4초 간격으로 계속 재시도하고, 한 번의 시도는 5초 안에 포기합니다 |
| "pi 프로세스가 종료되었습니다" | 세션 닫기 후 다시 열기. `pi`가 `PATH`에 있는지, 모델 서버가 살아 있는지 |
| 다른 기기에서 주소가 안 열림 | `--host 0.0.0.0`으로 띄웠는지, 같은 네트워크(VPN)인지 |
| 바뀐 UI가 안 보임 | `npm run build` → `touch src/web.rs` → `cargo build --release` → 서버 재시작 후 강력 새로고침 |
| Git 탭 "저장소가 아닙니다" | 세션 폴더가 git 저장소 안에 있는지 |
